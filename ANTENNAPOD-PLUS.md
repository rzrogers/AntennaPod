# AntennaPod+

AntennaPod+ is a modified version of [AntennaPod](https://github.com/AntennaPod/AntennaPod), made by rzrogers for personal use. Work started on 2026-10-23.

- **License:** GNU General Public License, version 3 (GPL-3.0), the same as AntennaPod. See [LICENSE](LICENSE).
- **Source code:** https://github.com/rzrogers/AntennaPod (branch `playlists`). Each release links to the exact commit it was built from.
- **Support:** The AntennaPod team does **not** provide support for this unofficial version. Please don't report AntennaPod+ problems to AntennaPod's forum or bug tracker.

## Changes from AntennaPod

- **Own app ID and name:** installs as "AntennaPod+" with app ID `de.danoeh.antennapod.plus`, so it sits beside official AntennaPod.
- **Version suffix:** the version name ends in `-plusN`, where N is the build number.
- **Build workflow:** `.github/workflows/antennapod-plus-build.yml` builds a signed APK on every push to `playlists` and attaches it to a GitHub release.
- **Notice in Settings:** the notice for unofficial versions now names AntennaPod+, its author, its license and its source code. The "Project" section of Settings stays hidden, because its links go to the AntennaPod team.
- **Landing page:** `.github/README.md` is the fork's GitHub landing page; AntennaPod's own `README.md` is unchanged.
- **Playlists:** saved playlists beside the single queue.
  - Storage: new database tables (`Playlists`, `PlaylistItems`, `PlaylistFeeds`, and `DelayedDeletions` from build 8), created when the database opens if they're missing. AntennaPod's own tables and database version number are unchanged, so AntennaPod can still import an AntennaPod+ database export (it ignores the extra tables). When episodes or shows are deleted, their playlist entries are deleted too.
  - Screens (build 5): a "Playlists" item in the main menu (it can be reordered, hidden or put in the bottom bar like the others) opens a list of playlists with their episode counts; create, rename and delete playlists there. Each playlist screen has drag-to-reorder, swipe-to-remove with undo, and a Sort menu that rearranges the playlist once.
  - "Add to playlist…" (build 5) in the episode long-press menu, the multi-select menu and the episode screen's menu: a pop-up of playlists with checkboxes, plus "New playlist…". One episode can be in several playlists.
  - Swipe action (build 6): "Add to playlist…" can be chosen as a left or right swipe action on any list; it opens the same pop-up.
  - Per-show auto-add (build 6): each show's settings have "Add new episodes to playlist" (None or one playlist). New episodes found by a refresh are added to the end of that playlist, oldest first. The show's existing "New episodes" setting still applies, so they also appear in the Inbox unless that show is set to "Nothing".
  - Playlist auto-download (build 7): each playlist's ⋮ menu has "Automatic download" (Off, the next 1/2/3/5/10 episodes, or all). It uses AntennaPod's own automatic-download conditions (Wi-Fi, battery, Episode limit), works even when global automatic download is off, and playlist episodes go first when the Episode limit is tight. A download icon marks those playlists on the Playlists screen. Automatic cleanup never deletes downloads of episodes that are in any playlist, as for queued episodes. Hooks: `AutomaticDownloadAlgorithm`, the three cleanup algorithms, and a small listener registered in `PodcastApp` that re-runs automatic download when playlists or played status change. The `Playlists` table gains an `auto_download` column, added on database open if missing.
  - Finishing removes (builds 5–6): finishing an episode (playing it to the end or marking it played) removes it from every playlist. Already-played episodes can still be added, to listen again; they stay until they're finished again. A small hook in `PodDBAdapter.setFeedItemsRead` and a database trigger (for other paths that change an episode to played) do this.
  - Play and save back (build 8): each playlist screen has a Play button that replaces the queue with the playlist, in its order, and starts the first episode (partly played ones resume). That playlist is then "loaded": the queue's title shows its name, the Playlists screen marks it "Playing in queue", and every queue change (adding, removing, reordering, finishing) is saved back to it (while a playlist is loaded, marking a queued episode played also takes it out of the queue, so the two stay the same). Changes made on the loaded playlist's own screen go to the queue in the same spot. Playing another playlist switches over; the queue's ⋮ menu has "Unload playlist", and "Clear queue" unloads too, with the playlist keeping its episodes. With nothing loaded, the queue's ⋮ menu has "Save as playlist…". "Keep queue sorted" is paused while a playlist is loaded. Deleting the loaded playlist leaves the queue as an ordinary queue. Episodes with no audio can't be added to playlists and are skipped when one is played. Hooks: `PodDBAdapter.setQueue` copies the queue into the loaded playlist inside the same transaction, `PodDBAdapter.clearQueue` unloads, `DBWriter.runOnQueueThread` lets playlist writes run on AntennaPod's database thread, `UserPreferences.isQueueKeepSorted` checks a "playlist loaded" preference, `QueueFragment` adds the title, menu items and sort-dialog change, and `FeedItemMenuHandler` hides "Add to playlist…" for episodes without audio.
  - Delayed automatic deletion (build 8): Settings → Downloads → Automatic deletion has "Delete after" (Immediately, the default and official behaviour; 15 minutes; 1 hour; 1 day). When automatic deletion would delete a finished episode's download, it waits that long instead, then deletes it unless the episode is back in the queue or a playlist, is playing, or isn't downloaded any more. A check runs about every 15 minutes. New table `DelayedDeletions`; hooks in both playback services and `FeedItemMenuHandler` call `DelayedDeletion.deleteOrSchedule` in place of the direct delete.
